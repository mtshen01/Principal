> 前置工程已就绪：app.js 已拆到 1752 行 + 15 模块（ES modules 无构建），面板/存储/原语全部模块化，
> 三道 e2e 门禁（panels-smoke / steer-bubble / mcp-tab）可护航大改。

## 现状形态
单页三栏：左侧栏（会话列表 + 工具清单二态切换）｜主区（聊天流 + 嵌入式面板 settings/tasks/logs/json-tool 单入口互斥）｜右下 fab（模型/强度/权限模式弹层）。本质是「聊天台 + 管理面板」，不是「编辑器」。

## Roadmap 原语（用户 2026-07 提出）
「侧栏重塑为会话目录、去文件树、内置工具面板——Cursor 式外壳」。

## 待拍板的问题（按影响排序）

1. **「会话目录」的组织维度**：现状按时间排平铺（本地+磁盘历史合并）。改版选项：
   - A. 按**项目目录（cwd）分组**的树：一个项目一个分组，展开见该项目会话（贴近「编辑器打开工作区」心智，推荐）
   - B. 手动文件夹/标签（用户自建分组，管理成本高）
   - C. 维持时间线 + 强化搜索过滤（改动最小）
2. **多会话并行的可视形态**：现状后台会话仅列表徽标。选项：
   - A. **Tab 栏**（Cursor/IDE 心智：顶栏多 tab 切换活跃会话，推荐）
   - B. 分屏（两会话并排，复杂度高，YAGNI？）
   - C. 维持单视图 + 徽标
3. **工具面板归置**：现状 json-tool 等藏在侧栏二态。选项：
   - A. 右侧可收纳 Dock（编辑器右栏心智，与聊天并存不互斥，推荐）
   - B. 维持主区互斥面板
4. **移动端是否保**：现状有移动适配。Cursor 式布局在窄屏基本不可用——降级策略（保聊天弃编辑器态？）需要明确。
5. **范围**：纯外壳重排（CSS Grid + 现有模块重挂载，2-3 天量级）vs 连交互升级（tab 化 + 会话目录树 + dock，1-2 周量级）。

## 技术路径（无论选哪组答案都成立）
- 布局骨架先行：`index.html` 改 CSS Grid 区块（sidebar / tabbar? / main / dock?），现有模块按区重挂载——**面板模块已解耦，改版主要是壳层工作**。
- P3 剩余的聊天核心（send/stream/打字机）在改版中顺势按新交互重写，**不要在改版前机械拆**（已在 appjs-split spec 定论）。
- e2e 门禁随布局同步改选择器，先改测试基线再动壳（拆分工程验证过的流程）。

## 建议
先拍 1/2/3 三个问题（我的推荐：1A + 2A + 3A = 完整 Cursor 式），范围选「纯外壳重排」起步——一个可见的新骨架落地后，tab 化与会话目录树分两个迭代跟进，每步 e2e 护航。
