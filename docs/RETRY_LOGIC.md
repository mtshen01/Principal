# 🔄 Claude Agent SDK 流式重试机制

## 问题

⚠️ `Response stalled mid-stream` 错误频发 —— API 流式响应在传输中途中断，导致任务失败。

**根因**：网络不稳定、代理超时、API 偶发故障等导致长连接被截断。

---

## 解决方案

在 `src/integrations/claude.js` 的 `runClaude()` 函数加入了 **指数退避重试机制**：

### 核心特性

| 特性 | 说明 |
|------|------|
| **自动重试** | 流式响应中断时自动重试，不中断用户交互 |
| **错误识别** | 只重试 `stalled`/`mid-stream` 网络错误，权限/请求错误直接失败 |
| **指数退避** | 1s → 2s → 4s → 8s（最长 10s），避免雪崩 |
| **可配置次数** | 默认 3 次重试（共 4 次尝试），可通过 `maxRetries` 参数调整 |
| **日志追踪** | 每次重试记录 attempt/maxRetries，便于诊断 |

### 使用

#### 默认重试 3 次
```js
await runClaude('任务 prompt', {
  // ... 其他参数
});
```

#### 自定义重试次数
```js
await runClaude('任务 prompt', {
  maxRetries: 5, // 重试 5 次（共 6 次尝试）
  // ... 其他参数
});
```

#### 禁用重试（应急）
```js
await runClaude('任务 prompt', {
  maxRetries: 0, // 直接失败，不重试
  // ... 其他参数
});
```


```
✖ 重试 3 次后仍失败 { ms: 10200 }  // 3 次都失败，抛错
```

## 技术细节

### 重试发生的位置
- **query 创建/流开启** 时中断 → 捕获异常，重试
- **中间流式消息处理** 时中断 → 捕获异常，重试
- 已成功的 result 消息之后的错误也会重试

### 输入队列处理
- **非流式输入**（普通 prompt）：重试时重新使用相同 prompt
- **流式输入**（steering 模式）：重建队列并重用原始 prompt 和之前 push 的插话
  - ⚠️ **已执行的工具结果不会重复** ——SDK 内部维护会话状态，避免重复

### 不重试的错误
- `400 Bad Request`（参数错误）
- `401 Unauthorized`（密钥失效）
- `403 Forbidden`（权限不足）
- 其他显式应用层错误

---

## 性能影响

- ✅ **正常情况**（网络稳定）：无额外延迟，直接成功
- ⚠️ **网络不稳定**：最多额外延迟 = 1s + 2s + 4s + 8s = **15s**（极端情况）
- ✅ **自动压缩**配合工作：重试完成后消息队列长度不会爆炸
