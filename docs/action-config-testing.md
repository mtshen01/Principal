## 前置检查清单

测试前，确认以下环境和依赖已就绪：

- [ ] **Node.js 版本**  
  ```bash
  node --version  # 应为项目支持的版本
  ```

- [ ] **依赖已安装**  
  ```bash
  npm ls uuid  # uuid 包应存在
  npm ls express  # express 应存在
  ```

- [ ] **项目配置完整**  
  确认存在：
  - [ ] `src/shared/config.js` — 包含 `scripts` 字段
  - [ ] `src/store/` 目录 — 存在 action-configs.js / user-vars.js / action-log.js
  - [ ] `src/features/action-runner/` 目录 — 包含 slot-filler.js / script-runner.js
  - [ ] `scripts/` 目录 — 至少存在 `reset_onboarding.py` 或可测试的脚本

- [ ] **飞书机器人就绪**  
  - [ ] 机器人应用已创建并配置
  - [ ] 机器人 webhook 已配置，指向本地或测试环境
  - [ ] 机器人具有发送消息的权限
  - [ ] 与机器人的对话渠道已打开（如测试群组或 1v1 对话）

- [ ] **测试账户准备**  
  - [ ] 至少 2 个飞书账户用于多客户端隔离测试
  - [ ] 各账户的 open_id 已获取（用于查看 user-vars.json）

## 启动与初始化测试

### T1.1 服务启动验证

```bash
# 在项目根目录执行
npm start
```

**预期结果**：
- [ ] 后台输出 `🚀 Server running on http://localhost:3000`
- [ ] 无 import/syntax 错误
- [ ] Web 服务在端口 3000 可访问

**检验方法**：
```bash
curl http://localhost:3000
```
应返回 HTTP 200 和 HTML 内容。

### T1.2 默认配置文件创建

启动后，检查项目根目录：

```bash
ls -la action-configs.json user-vars.json action-log.jsonl
```

**预期结果**：
- [ ] `action-configs.json` 已创建（大小 > 100 bytes）
- [ ] `user-vars.json` 已创建或为空（大小 >= 2 bytes，如 `{}` 或 `[]`）
- [ ] `action-log.jsonl` 已创建（可为空文件）

### T1.3 默认配置内容验证

```bash
cat action-configs.json | jq .
```

**预期结果**：
- [ ] 文件是有效的 JSON 数组
- [ ] 至少包含一个配置对象
- [ ] 对象包含字段：
  - `id` — UUID 格式
  - `name` — 「清理账号数据」（或类似）
  - `keywords` — 数组，包含「清理」等关键词
  - `scriptName` — 「reset_onboarding.py」
  - `variables` — 数组，包含 `phone` 和 `env` 变量定义
  - `enabled` — `true`
  - `createdAt` / `updatedAt` — ISO8601 时间戳

### T1.4 脚本文件检查

```bash
ls -la scripts/reset_onboarding.py
```

**预期结果**：
- [ ] 脚本文件存在
- [ ] 脚本可执行（或项目配置的 Python 可运行它）

**可选**：测试脚本参数解析

```bash
python scripts/reset_onboarding.py --env test --phone 13800138000
```

应输出相关日志或完成清理逻辑（具体输出由脚本实现决定）。

## API 端点测试

### T3.1 GET /api/actions（列出全部配置）

```bash
curl http://localhost:3000/api/actions
```

**预期结果**：
- [ ] HTTP 200
- [ ] 返回 JSON 数组
- [ ] 数组包含至少 1 个对象（默认的「清理账号数据」）
- [ ] 每个对象包含字段：`id`, `name`, `description`, `keywords`, `scriptType`, `scriptName`, `permission`, `enabled`, `variables`, `createdAt`, `updatedAt`

**格式验证**：
```bash
curl http://localhost:3000/api/actions | jq '.[0]'
```

应返回第一个配置的完整信息，无解析错误。

### T3.2 POST /api/actions（创建新配置）

```bash
curl -X POST http://localhost:3000/api/actions \
  -H 'Content-Type: application/json' \
  -d '{
    "name": "API 创建配置",
    "description": "通过 API POST 创建",
    "keywords": ["api", "create"],
    "scriptType": "python",
    "scriptName": "reset_onboarding.py",
    "permission": "guest",
    "enabled": true,
    "variables": [
      {
        "name": "test_var",
        "label": "测试变量",
        "prompt": "请输入测试值",
        "required": true,
        "persistent": false
      }
    ]
  }'
```

**预期结果**：
- [ ] HTTP 200
- [ ] 返回 JSON 对象，包含新配置的完整信息
- [ ] 返回值包含系统生成的 `id`（UUID 格式）
- [ ] 返回值包含 `createdAt` 和 `updatedAt` 时间戳

**保存测试配置 ID**：记录返回的 `id` 值，后续编辑/删除用

### T3.3 PUT /api/actions/{id}（更新配置）

使用上一步得到的 `id`：

```bash
# 替换 {id} 为实际值
curl -X PUT http://localhost:3000/api/actions/{id} \
  -H 'Content-Type: application/json' \
  -d '{
    "name": "API 创建配置 - 已更新",
    "description": "通过 API PUT 更新"
  }'
```

**预期结果**：
- [ ] HTTP 200
- [ ] 返回更新后的配置
- [ ] `name` 字段为新值
- [ ] `updatedAt` 时间戳变化（比 `createdAt` 更晚）
- [ ] 其他字段（如 variables）保持不变

**验证列表**：
```bash
curl http://localhost:3000/api/actions | jq '.[] | select(.name | contains("API 创建配置 - 已更新"))'
```

应返回该配置。

### T3.4 GET /api/scripts（列出脚本文件）

```bash
curl http://localhost:3000/api/scripts
```

**预期结果**：
- [ ] HTTP 200
- [ ] 返回 JSON 数组
- [ ] 数组包含字符串（脚本文件名）
- [ ] 至少包含 `reset_onboarding.py`（或项目中的其他脚本）
- [ ] 仅包含 `.py` 和 `.js` 扩展名的文件

**示例返回**：
```json
["reset_onboarding.py", "send_sms.js"]
```

### T3.5 DELETE /api/actions/{id}（删除配置）

使用前面 POST 返回的 `id`：

```bash
curl -X DELETE http://localhost:3000/api/actions/{id}
```

**预期结果**：
- [ ] HTTP 200
- [ ] 返回 `{"success":true}` 或类似确认消息

**验证删除**：
```bash
curl http://localhost:3000/api/actions | jq '.[] | select(.id == "{id}")' | wc -l
```

应返回 `0`（配置已移除）。

### T3.6 错误处理

**删除不存在的配置**：
```bash
curl -X DELETE http://localhost:3000/api/actions/fake-uuid-12345
```

**预期结果**：
- [ ] HTTP 404
- [ ] 返回错误信息，如 `{"error":"配置不存在"}`

**POST 无效数据**：
```bash
curl -X POST http://localhost:3000/api/actions \
  -H 'Content-Type: application/json' \
  -d '{"name": "缺少必需字段"}'
```

**预期结果**：
- [ ] HTTP 400
- [ ] 返回错误信息

## 飞书 E2E 测试

- [ ] 飞书机器人已启动并连接
- [ ] 可以在飞书群组或 1v1 对话中与机器人交互

## 日志与审计测试

### T5.1 执行日志记录

在飞书触发任意动作（如上文的清理操作），执行成功后，检查日志文件：

```bash
tail -5 action-log.jsonl
```

**预期结果**：
- [ ] 文件存在（`action-log.jsonl`）
- [ ] 最后一行是新近执行的日志
- [ ] 日志是有效的 JSON 格式

### T5.2 日志内容完整性

格式化最后一条日志查看：

```bash
tail -1 action-log.jsonl | jq .
```

**预期结果**：
- [ ] 包含字段 `time`（ISO8601 格式）
- [ ] 包含字段 `userId`（飞书 open_id）
- [ ] 包含字段 `actionId`（UUID）
- [ ] 包含字段 `actionName`（如 「清理账号数据」）
- [ ] 包含字段 `vars`（对象，包含执行时使用的变量）
- [ ] 包含字段 `ok`（boolean，true 为成功）
- [ ] 包含字段 `code`（number，脚本退出码）

### T5.3 敏感字段脱敏

查看日志中的 phone 字段：

```bash
tail -1 action-log.jsonl | jq '.vars.phone'
```

**预期结果**：
- [ ] phone 值格式为 `1XX****XXXX`（前 3 位 + 4 个 * + 后 4 位）
- [ ] 示例：`13800138000` 脱敏为 `159****9503`

**错误示例**（不应出现）：
```
"159****503"    # ✗ 后面只有 3 位
"13800138000"   # ✗ 未脱敏
"***9503"       # ✗ 前面过多星号
```

### T5.4 多次执行的日志累积

执行 3 次不同的动作（或相同动作多次），检查日志：

```bash
wc -l action-log.jsonl
# 应返回至少 3
```

**预期结果**：
- [ ] 每次执行都追加新行（不覆盖）
- [ ] 行数逐次增加

### T5.5 日志解析

使用 `jq` 提取特定信息：

```bash
# 查询所有成功的执行
cat action-log.jsonl | jq 'select(.ok == true)'

# 查询特定用户的日志
cat action-log.jsonl | jq 'select(.userId == "ou_xxxxx")'
```

- [ ] 系统识别为失败
- [ ] 日志记录 `ok: false, code: 1`
- [ ] 机器人回复失败消息
